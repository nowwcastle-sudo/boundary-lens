# Boundary Lens 로컬 확장 설계

- 상태: 2026-09-20 사용자 상세 설계 승인 ("설계 승인"), 구현 전
- 기준 코드: b8d9b0abe078c5689db7f33d0bb0b8eb0e561921
- 목표: 한 사건의 경로·실행 환경·선택한 로그 증거를 함께 읽고 전달할 수 있게 한다.
- 이전 비목표인 자동 복구, 권한 변경, 원격 접속, 광범위 디스크 검색은 유지한다.

## 1. 기존 기능과 새로운 경계

기존 `BoundaryLens.ps1 -Workspace -FailedPath -Format`과 JSON schema 1은
유지한다. 현재 네이티브 핸들 수집, 오류·UNKNOWN, 개인정보 최소화,
읽기 전용 증거를 바꾸어 확장 기능을 쉽게 만들지 않는다.

새 로컬 작업공간은 별도 companion 진입점으로 구성한다. 기존 진단의
출력을 소비하고 사건 문맥을 덧붙이는 책임과, 조사 대상 파일을 읽는
진단기의 책임을 구분한다. 별도 서버·설치 서비스·외부 의존성을 추가하지
않고 PowerShell 7과 .NET으로 구현한다. 다른 프로그램을 자동 실행하거나
종료하지 않는다.

## 2. 추가 기능과 수용 조건

| ID | 기능 | 완료로 인정할 행동 |
|---|---|---|
| BL-L01 | 실행 문맥 연결 | 명시한 제품·버전·오류 코드·발생 시각·URI를 받아 기존 경로 증거 옆에 표시한다. 제공 정보와 직접 관측을 구분한다. |
| BL-L02 | 선택한 로컬 프로세스 관측 | 명시한 PID 한 개의 이름·시작 시각·접근 가능한 기본 메타데이터만 읽는다. 종료·PID 재사용·권한 거부를 관측 실패로 보존한다. |
| BL-L03 | 선택한 로그 가져오기 | 지정한 로컬 JSON/JSONL 파일만 제한된 크기로 읽고 허용된 오류 필드만 추출한다. 원문 대화·환경변수·명령줄·임의 메시지를 보고서에 복사하지 않는다. |
| BL-L04 | 볼륨·필터 증거 연결 | 대상 볼륨의 확인 가능한 파일시스템 정보와 사용자가 가져온 필터 관측을 출처와 함께 표시한다. 가져온 값이 실측인 것처럼 표시하지 않는다. |
| BL-L05 | 경로·URI 관계 설명 | URI의 scheme과 로컬/원격 표현을 분석하되 URI 대상에 접속하지 않는다. 실제 매핑 근거가 없으면 문자열 유사성으로 동일 대상이라고 단정하지 않는다. |
| BL-L06 | 전달용 JSON/HTML | 명시한 새 출력 경로에 민감정보를 최소화한 사건 요약과 다음 관측을 저장한다. HTML은 스크립트·외부 자원이 없는 열람용이다. |

사건 입력은 `boundary-incident/1`로 버전 관리한다. 선택 항목은 product,
version, error_code, occurred_at, runtime_uri, process_id, supplied_observations다.
unknown 필드·중복 JSON 키·잘못된 타입·제한 초과는 고정된 오류로 거절한다.
원격 URI를 문자열 자료로 받는 것과 원격 파일을 탐색하는 것은 다르다.

각 관측은 kind, provenance, status, value, observed_at, error_code를 가진다.
provenance는 local-query 또는 operator-supplied다. 시각·값을 얻지 못하면
null과 원인을 남기며 현재 시각이나 추측값으로 채우지 않는다.

## 3. 안전한 입출력

- 파일 입력당 1 MiB, 로그 입력 합계 4 MiB, 레코드 10000개, 레코드당
  문자열 4096자로 제한한다. 초과 시 부분 성공으로 보이지 않게 한다.
- 입력은 명시한 로컬 일반 파일만 허용한다. UNC·원격 드라이브·reparse
  입력은 거절한다. 읽기 도중 교체·변화를 검출하면 결과를 폐기한다.
  이 검사가 전체 OS의 네트워크 차단을 보증한다는 주장은 하지 않는다.
- 기본 전달본에서 사용자 홈·원시 계정/SID·호스트명·토큰·명령줄·로그
  원문을 제거한다. 경로는 사건 내 별칭으로 표시한다. 해시도 연결 가능한
  정보일 수 있으므로 익명화 완료라고 표시하지 않는다.
- 저장은 사용자가 지정한 별도 출력에만 한다. 기존 파일, 입력과 같은
  파일/하드링크, reparse 출력, 조사 경로 내부의 출력은 거절한다.
  실패한 산출물과 원래 입력은 보존한다.
- HTML 텍스트와 링크를 escape한다. 링크는 허용된 명시적 HTTPS 참조만
  클릭할 수 있고 자동 요청은 없다. 원본 로그·프로세스 메모리는 넣지 않는다.

## 4. 불완전한 관측과 호환성

추가 관측 실패는 기본 경로·ACL 증거를 지우지 않는다. 기존
RUNTIME_ENFORCEMENT_UNKNOWN은 유지한다. 프로세스 메타데이터나 로그
한 줄만으로 실제 접근 허용·차단 원인, ACL 정상, 네트워크 격리를 확정하지
않는다. 새 원인 후보는 사전에 정의한 근거가 있을 때만 추가한다.

내부 조합 모델은 원래 core_report와 추가 문맥을 구분한다. 전달본에는
core_summary, incident_context, observations, handoff_summary만 넣으며
core_summary는 최소화된 필드다. 원시 core_report는 전달본에 복사하지
않고 사용자의 별도 로컬 파일에 남는다.

## 5. 검증 기준

BL-L01–06마다 정상·빈 자료·잘못된 타입·자원 경계·권한/수집 실패를
실행한다. URI 접속 금지, 토큰/경로 유출 방지, HTML 주입 방지, 입력
불변, 출력 충돌/하드링크·reparse 거부, PID 종료/재사용을 별도로 고정한다.
제공한 거짓 문맥이 observed나 SAFE로 승격되는 음성 사례를 포함한다.

기존 모든 CI 단계와 네이티브 회귀를 다시 실행한다. companion의 명시적
결과 저장을 기존 수집기의 읽기 전용 허용 목록에 섞지 않는다. 새 package
allowlist는 구현 파일 구성이 확정된 실행 계획에 정확히 나열하고, 이전
릴리스와 별도의 후보 파일에서 source/hash/member를 확인한다.

요구사항별 구현 위치·테스트 이름·실행 source·종료 코드·결과를 대조표로
남긴다. 사용 불가·권한 부족·미지원은 통과로 세지 않는다.

## 6. 외부 연동으로 넘어갈 조건

로컬 관측과 명시적으로 가져온 자료로도 특정 사건의 필수 증거를 얻지
못할 때만 2단계를 검토한다. 그때 필요한 제품 로그 schema, WSL 배포판,
SSH 대상, 원천·권한을 구체적으로 제시한다. 자동 원격 탐색이나 관리자
권한 상승은 이번 설계에 포함하지 않는다. 부족한 증거를 UNKNOWN으로
남기는 기능과 외부 환경을 실제 지원하는 기능을 혼동하지 않는다.
